# POLUTONE — интернет-магазин

Next.js 16 + Payload CMS 3 + PostgreSQL + Tailwind 4. Фото — Timeweb S3.
Дизайн-правила: `../DESIGN_SYSTEM.md` (вне репозитория, рядом с брендбуком).

## Запуск локально

1. PostgreSQL 17 с базой `polutone`.
2. `cp .env.example .env` и заполнить значения (S3 можно оставить пустым — тогда фото сохраняются в `/media`).
3. ```
   npm install
   npm run dev
   ```
   Сайт — http://localhost:3000, админка — http://localhost:3000/admin.

## Структура

- `src/app/(frontend)` — сайт (токены бренда в `globals.css`, шрифты в `fonts.ts`)
- `src/app/(payload)` — админка и API Payload
- `src/collections` — коллекции Payload
- `src/lib` — общие модули (`s3.ts` — подключение Timeweb S3)
- `tests/unit`, `tests/int`, `tests/e2e` — тесты

Ключи и пароли — только в `.env`, он не коммитится.

## Тестовый сайт на Vercel

Vercel собирает сайт из GitHub после каждого коммита (скрипт `vercel-build`: миграции базы → тестовые данные, если включены → `next build`).

Переменные окружения в Vercel (Settings → Environment Variables):

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | Строка подключения Neon (pooled, `...-pooler...neon.tech/...?sslmode=require`) |
| `PAYLOAD_SECRET` | Длинная случайная строка, своя для этого сайта |
| `CATALOG_SOURCE` | `mock` |
| `SITE_PASSWORD` | Пароль на весь сайт (имя пользователя любое); пусто — сайт открыт |
| `SEED_TEST_DATA` | `true` — при сборке создать страницы «Информация», тестовый каталог и загрузить тестовые фото |
| `BLOB_READ_WRITE_TOKEN` | Добавится сам, когда подключите хранилище: Vercel → Storage → Create → Blob → Connect to project. Нужен для фото |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Уведомления о заказах (необязательно) |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | Оплата через ЮKassa (тестовый или боевой магазин). Пусто — оплата на сайте выключена |
| `CRON_SECRET` | Длинная случайная строка: защищает ежедневную отмену неоплаченных заказов (`vercel.json`) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` | Письма покупателю; пусто — письма только в журнале |

## Оплата (ЮKassa)

- Покупатель оформляет заказ → вещи откладываются на 60 минут → сайт создаёт платёж и переводит на страницу ЮKassa → после оплаты возвращается на `/order/<код>`.
- Статус платежа сайт узнаёт двумя путями: уведомление ЮKassa на `POST /api/payments/yookassa` и проверка при возвращении покупателя. Тело уведомления не доверяется: платёж перечитывается из API ЮKassa, сверяются заказ и сумма.
- В ЮKassa: Интеграция → HTTP-уведомления → адрес `https://<сайт>/api/payments/yookassa`, события `payment.succeeded` и `payment.canceled`.
- Чек 54-ФЗ — «Чеки от ЮKassa»: состав заказа уходит в платёж, ставка НДС — `YOOKASSA_VAT_CODE` (1 — без НДС).
- Неоплаченный за 60 минут заказ отменяется, вещи возвращаются в остаток: при каждом просмотре корзины и оформлении, на странице заказа и по расписанию (`GET /api/cron/expire-orders` с `Authorization: Bearer CRON_SECRET`; на Vercel — раз в сутки, на своём сервере — cron каждые 5 минут).
- Локально без ключей вместо ЮKassa открывается тестовая страница `/payment/mock/<id>` («Оплатить» / «Отказаться»), деньги не списываются. На сервере без ключей оплата выключена.
- Пути `/api/payments/yookassa` и `/api/cron/expire-orders` открыты без `SITE_PASSWORD`.

## Доставка (СДЭК)

- В оформлении: город из подсказок СДЭК → пункт выдачи (список с поиском и карта Яндекса, если задан `NEXT_PUBLIC_YANDEX_MAPS_KEY`) или курьер → цена и срок считаются на сервере и входят в оплату. Яндекс Доставка и Почта России скрыты до фазы 4 (`CHECKOUT_SERVICES`).
- Тарифы: 136 «Посылка склад-склад» (в пункт), 137 «склад-дверь» (курьер): посылки сдаются в пункт СДЭК. Вес — «Вес одной вещи» у категории + упаковка; коробка и порог бесплатной доставки — «Настройки сайта» → «Доставка».
- После оплаты заказ создаётся в СДЭК сам. Если не вышло — сообщение в Telegram и кнопка «Передать в СДЭК» в заказе. Статусы приходят на `POST /api/delivery/cdek` (подписка: `npm run cdek -- webhook https://<сайт>/api/delivery/cdek`), сайт перечитывает заказ из СДЭК; «Передан в доставку» → письмо с трек-номером, «Доставлен».
- Коды города и пункта сдачи: `npm run cdek -- find "Красная Поляна"`. При сохранении настроек сайт проверяет их в СДЭК.
- Карта пунктов — Яндекс Карты JS API 2.1 по бесплатной лицензии (условия: yandex.ru/legal/maps_api). Чтобы оставаться в её рамках: карта грузится только по кнопке «Показать на карте»; используется только показ карты и меток (координаты — от СДЭК; Геокодер и Геосаджест с лимитом 1000 запросов/сутки не используются); логотип, копирайты и «Открыть в Картах» не скрываются; без ключа или при блокировке остаётся список. Ключ — `NEXT_PUBLIC_YANDEX_MAPS_KEY`, ограничьте его в кабинете Яндекса адресами сайта (HTTP Referer). При суточной аудитории больше 100 000 — сообщить в Яндекс; для коммерческого режима — платный тариф.
- Ключи `CDEK_CLIENT_ID`, `CDEK_CLIENT_SECRET` (`CDEK_TEST=true` — тестовое окружение). Без ключей локально — тестовая доставка с вымышленными городами, на сервере — «стоимость сообщим».

База: в Vercel → Storage → Create Database → Neon — переменная `DATABASE_URL` добавится сама.

Тестовые данные создаются при сборке (`npm run seed:build`), если `SEED_TEST_DATA=true`: при первой сборке —
страницы «Информация» и 6 тестовых изделий (опубликованы); повторные сборки ничего не дублируют и не меняют
правки из админки.

Тестовые фото (AI-визуализации, не настоящие изделия) лежат в `test-data/photos` и загружаются в Vercel Blob при сборке, если хранилище подключено. Без него сборка их пропускает. Сайт с ними держите под паролем (`SITE_PASSWORD`). Локально: `npm run seed:photos`.
